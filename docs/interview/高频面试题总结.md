## 一、项目深挖（几乎必问）

### Q1. 用一句话介绍你的文档/编辑器项目？

**短答：** Notion 式块文档工作台：对外是带 UUID 的 `Block[]`，编辑用 Tiptap/ProseMirror，协作与持久化用 Yjs + Hocuspocus 写 PostgreSQL；Web 为 Next.js，业务 API 为 NestJS，编辑器拆成可 MIT 发布的 monorepo 包。

**追问方向：** 为什么块模型不直接存库？协作和 REST 各自负责什么？

---

### Q2. 从用户敲一个字到另一台设备看到，数据怎么走？

**短答：**

1. 本地 PM `Transaction` → Tiptap Collaboration 扩展写入 `Y.XmlFragment`。
2. Yjs 产生 update → WebSocket（Hocuspocus Provider）发到协作服务。
3. 服务端广播 + 定时/触发持久化（`yjs_update` / snapshot 表）。
4. 对端 Provider 合并 CRDT update → PM 文档更新 → React 重渲染。

**易错点：** 正文真相源是 **Y.Doc**，不是 Postgres 里的 Block JSON；Block[] 是转换视图。

---

### Q3. 为什么 monorepo 拆 `editor-core` / `editor-react` / `editor-shadcn`？

**短答：**

- **core**：无 React，块 schema、PM 转换、Markdown、Yjs 迁移——可跑在 Node（API、测试、AI 管道）。
- **react**：Provider、协作会话、Hooks。
- **shadcn**：可替换的 UI（工具栏、NodeView、主题）。

**目的：** Headless 嵌入、树摇、避免 UI 库绑死业务。

---

### Q4. Next.js 里文档页为什么大量 Client Component？

**短答：** 编辑器、Yjs、选区、快捷键、拖拽依赖浏览器 DOM 与 WebSocket，无法 RSC 直出交互态。列表/布局可 Server 拉元数据，**编辑区必须客户端挂载**；鉴权 Cookie 经同源 rewrite 到 API。

---

### Q5. 分享链接只读和 workspace 成员编辑，权限在哪校验？

**短答：** **多层校验**：Nest Guard 读 Session + 文档/工作区成员表；分享 token 单独路由与能力位；前端隐藏按钮不能代替后端。Server Actions / API 均需 **动作内鉴权**（不可只信中间件）。

→ 详见 [auth-session-architecture](./auth-session-architecture.md)。

---

## 二、React / Next.js

### Q6. React 19 和 18 你在项目里会关心的点？

**短答：** `ref` 作为普通 props；`use()` 读 Context（可条件调用）；并发特性配合 `useTransition` 做非紧急 UI（搜索、图谱）。编辑器主体仍要避免在 render 里重活。

---

### Q7. 如何减少编辑器周边组件的重渲染？

**短答：** 选区/工具栏状态与文档内容解耦；窄依赖的 Context；事件放 handler 而非 effect；大列表 `content-visibility`；静态 JSX 外提。避免在父组件内 **内联定义子组件** 导致整树 remount。

---

### Q8. RSC 边界传 props 要注意什么？

**短答：** 只传客户端用到的字段，避免整表 50 列下发；不要在 Server 侧对同一数组反复 `.map`/`.filter` 产生多份引用导致 payload 膨胀；可变形操作用 `.toSorted()` 等 immutable API。

---

### Q9. Server Actions 安全上有什么坑？

**短答：** 与公开 API 等价，**每个 mutation 内** 验 Session 与资源权限；校验输入 schema；勿把「仅 layout 挡掉」当唯一防线。

---

## 三、协作与 CRDT（Yjs）

### Q10. OT 和 CRDT 区别？为什么选 Yjs？

**短答：** OT 常需中心变换或严格顺序；CRDT 各端独立合并，最终一致，适合离线/弱网。Yjs 与 Tiptap/ProseMirror 集成成熟，Hocuspocus 提供鉴权与持久化钩子。

---

### Q11. Yjs 冲突怎么「解决」？

**短答：** 不是人工 merge conflict，而是 CRDT **确定性合并**；并发编辑同一位置会按内置规则收敛。产品层用版本快照/历史回滚处理「误改」，不是 OT 式锁。

---

### Q12. 协作断线重连要注意什么？

**短答：** Provider 重连后 sync；服务端需能提供 **缺失 update 或 snapshot**；避免未 sync 完就导出 Block[]；Awareness 单独通道（光标/在线态）。

→ 排错：[yjs-常见问题](../yjs-常见问题.md)。

---

## 四、ProseMirror / 块编辑器

### Q13. Transaction、Step、Plugin 各干什么？

**短答：** 用户操作生成 **Transaction**（含一个或多个 **Step**），PM 原子应用；**Plugin** 订阅 tr、装饰 DOM、处理 paste/keymap。Tiptap Extension 是 PM Plugin + schema 的封装。

---

### Q14. Block[] 和 PM 文档如何互转？为什么粘贴 Markdown 有时丢格式？

**短答：** `blocksToPmDoc` / `pmDocToBlocks` 走块 schema；Markdown 经 parser → Block[]，不支持的 AST 会降级或拆段。表格、嵌套列表、自定义块要在 schema 与 serializer 里 **显式对齐**。

→ 详见 [文档导入导出实现](./文档导入导出实现.md)。

---

### Q15. AI 流式写入为什么先草稿再接受？

**短答：** 避免未确认内容进入 Yjs 广播；本地 draft 扩展/预览，接受后再一次 transaction 进协作文档，便于撤销与成本控制。

---

## 五、NestJS / 数据层

### Q16. Nest 里 Guard、Interceptor、Pipe 执行顺序？

**短答：** 入站大致：**Middleware → Guard → Interceptor(before) → Pipe → Handler → Interceptor(after)**。鉴权放 Guard；DTO 校验放 Pipe。

---

### Q17. Prisma 在生产要注意什么？

**短答：** 迁移用 `migrate deploy`；连接池与 serverless（Neon）适配；避免 N+1（`include`/`select`）；事务包多步写。协作二进制与关系型业务表 **分表存储**。

→ 详见 [prisma-常见问题](../prisma-常见问题.md)。

---

### Q18. 为什么协作服务有时单独进程（collab）？

**短答：** WebSocket 长连接与 HTTP API 资源模型不同；独立扩容、重启不拖垮 REST；Hocuspocus 与 Nest 主进程解耦部署（如 Render 多 service）。

## 六、性能与工程化

### Q19. 大文档卡顿你怎么查？

**短答：** Performance 看 Long Task；React Profiler 看是否整页跟选区变；PM doc 节点数；协作 update 频率；考虑虚拟化仅适用于 **块列表 UI**，全文 PM 通常靠 schema 扁平化与 debounce Awareness。

---

### Q20. Monorepo 本地怎么保证改 core 后 web 生效？

**短答：** pnpm workspace 协议依赖；core 需 build/watch；Next `transpilePackages` 包进编译；改 schema 要跑 core 测试 + web 回归。

---

## 六（续）、补充高频题

### Q21. 文档进回收站后，协作里的 Yjs 数据怎么处理？

**短答：** 业务表 **软删除**（`deleted_at`），列表/搜索过滤；**不立刻删** Yjs 快照与 update，恢复时仍能从协作存储拉回正文。永久删除才走级联清理。这样「误删」可恢复，且与「元数据在 SQL、正文在 Yjs」的分工一致。

**追问：** 永久删除时要不要通知 Hocuspocus 清 room？取决于产品是否允许同一 `documentId` 复用。

---

### Q22. 块级评论怎么锚定到正文？光标跑了评论还准吗？

**短答：** 评论存 **`block_id`**（块 UUID），不绑 PM 内绝对字符 offset；渲染时在对应 `blockContainer` 旁挂 UI，点击评论 **scroll + focus 块**。块被删/合并时业务层决定归档或 orphan 处理。

**易错点：** 不要用纯文本 offset 做长期锚点——协作编辑下 offset 不稳定。

---

### Q23. 版本历史「保存版本 / 回滚」和实时协作是什么关系？

**短答：** 实时协作始终是 **当前 Y.Doc** 的多端合并；「保存版本」是 **额外拍快照**（命名版本）存库；回滚 = 用历史 snapshot/update **替换或合并** 当前 doc 的状态，再通过 Yjs 同步到其他客户端（需产品层提示「所有人将被回退」）。

**区别：** 日常编辑无版本号；版本历史是 **人为检查点**，不是 Git 式每次 keystroke。

---

### Q24. ⌘K 全文搜索为什么能搜到正文？

**短答：** REST 检索：标题/ID 走 SQL；正文需 **可搜索副本**——例如从 Yjs 快照或异步索引出的纯文本/Markdown，而不是打开 room 现算。命中摘要展示片段，打开文档仍走协作加载 Y.Doc。

**追问：** 索引滞后、大文档、权限（只能搜有权的 workspace）要在 API 层过滤。

---

### Q25. 如何新增一种块类型（例如自定义 callout）？

**短答：** 在 core 用 **`defineBlockSpec`**（或等价 registry）声明 `type`、props、PM `blockContent` 节点；注册 **NodeView**（react/shadcn）；补齐 `blocksToPmDoc` / `pmDocToBlocks`、Markdown/HTML 序列化、斜杠菜单项。缺一环就会在 **round-trip 或粘贴** 时丢块。

→ 详见 [editor-core-design](./editor-core-design.md)、[块编辑器架构](./block-editor-architecture.md)。

---

### Q26. 粘贴来自 Word / 网页的 HTML，你们怎么处理？

**短答：** 浏览器 `clipboard` → 优先解析 **HTML**，经 sanitize + 规则映射到块 schema（段落/标题/列表/链接）；搞不定则降级纯文本或拆成多块。与 **Markdown 粘贴** 是两条 pipeline，都要在 PM Plugin 里统一成 Transaction，再走 Yjs。

**面试点：** 说清「schema 是上限」——粘贴结果不能超出已实现的块类型。

---

### Q27. 为什么用 Session Cookie + DB 存 hash，而不是 JWT？

**短答：** 要 **服务端随时作废**（登出、改密、封禁）；JWT 无状态撤销麻烦。Cookie `HttpOnly` 降低 XSS 偷 token 风险；token 只存 **SHA256**，库泄露也不能直接冒充。代价是每次请求查库/缓存——可接受。

→ 详见 [auth-session-architecture](./auth-session-architecture.md)。

---

### Q28. 你们怎么测编辑器：`editor-core` 和 `apps/web` 分工？

**短答：** **core**：纯函数与 PM 转换、Markdown、块 schema——Vitest，无 jsdom 或轻量 DOM。**web**：React 组件、auth、导出菜单——Testing Library + mock fetch。**E2E** 只兜关键路径（登录、打开文档、协作 smoke），不全屏像素测 PM。

**原则：** 贵且脆的交互测在 core；UI 测行为不测实现细节。

## 七、算法与基础（笔试常见）

不要求 LeetCode 难题，但要 **写对 + 讲复杂度**：

| 类型 | 典型题 |
|------|--------|
| 哈希 / 双指针 | 两数之和、三数之和、无重复最长子串 |
| 栈队列 | 有效括号、最小栈、滑动窗口最大值 |
| 链表 | 反转、环检测、合并有序链表 |
| 二叉树 | 层序遍历、最近公共祖先、路径和 |
| 二分 | 搜索旋转数组、边界查找 |

**与本项目弱相关但常问：** 实现 LRU（Map + 双向链表）、防抖节流、深拷贝边界（循环引用）。
