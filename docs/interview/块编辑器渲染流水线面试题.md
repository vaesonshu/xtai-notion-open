## 1. 一句话结论（开场白）

> **Block[] 是对外文档协议；Tiptap/ProseMirror 是编辑与 DOM 引擎；屏幕上的 HTML 不是 `blocks.map()` 画出来的，而是 PM `EditorView` 增量 patch 出来的。**  
> 需要块数据时，用 `pmDocToBlocks` 从当前 PM 状态**反查**，不是用 React state 驱动每个字符。

## 3. 面试问答：为何 Block[] + 仍用 Tiptap？

### Q1. 项目明明是 blocks，为什么 DOM 里还有 Tiptap/ProseMirror？

**短答：** Block 是**产品和 API 的抽象**；Tiptap 是**实现输入、选区、协作、表格、IME 的引擎**。二者通过自定义 PM schema（`blockGroup` → `blockContainer` → `blockContent`）和 `blocksToPmDoc` / `pmDocToBlocks` 绑在一起。

**可展开：**

| 若只有 Block[] | 若只有 PM |
|----------------|-----------|
| 要自己实现 contenteditable、Undo、协作 | API/服务端/测试全绑 schema |
| 难以复用 Tiptap 生态 | 产品「一块一行」语义弱 |

本项目路线与 BlockNote 同类：**对外块 API，对内 PM**。

---

### Q2. 用户看到的 `data-node-type="blockGroup|blockContainer"` 是什么？

**短答：** **PM 结构节点**，不是业务里的 `Block.type`。

- `blockContainer`：`data-id` = 块 UUID，供拖拽、评论、块 API、协同对齐。  
- 其内才是 `h1` / `p` / `li` / `table` 等 **blockContent**（对应 `Block.type`）。

**源码：** `packages/editor-core/src/core/schema/pm-nodes.ts`

---

### Q3. `editor.document` 和 PM 文档谁是「真相」？

**短答：** 编辑进行中 **PM `state.doc` 是编辑真相**；协作持久化时 **Y.Doc 是存储真相**（见分层总结）。`document` 是 getter，每次 `pmDocToBlocks(state.doc)`，**不是**渲染的数据源。

**源码：** `packages/editor-core/src/core/editor/block-editor.ts`

---

### Q4. React 会不会每个字都 setState 重绘正文？

**短答：** **不会。** 正文由 PM `EditorView` 直接维护 DOM。React 只负责 `EditorProvider`、`EditorContent` 容器，以及通过 `update` 事件可选订阅 `Block[]`（`useEditorBlocks`）。

**源码：**

- `packages/editor-react/src/react/editor-content.tsx` — 包装 `@tiptap/react`  
- `packages/editor-react/src/react/hooks/use-editor-blocks.ts`

## 4. 面试问答：挂载阶段（第一屏怎么出来）

### Q5. 从 `EditorProvider` 到出现可编辑区域，经过哪些步骤？

**短答（按序）：**

1. `block-editor-factory` / Provider 内 `new BlockEditor(...)`。  
2. `new Tiptap Editor({ extensions, editorProps, immediatelyRender: false })`。  
3. `buildBlockSchemaExtensions`：注册 `BlockDoc`、`BlockGroup`、`BlockContainer`、各块 `blockContent`、协作、Keymap 等。  
4. 若有初始 `Block[]`：`blocksToPmDoc` → `setContent`。  
5. `EditorContent` → `useEditorInstance()` 取 `blockEditor.tiptap` → 创建 **EditorView**，`contenteditable` 按 `renderHTML` / NodeView 输出 DOM。

**协作：** Y.Doc 非空时 `applyInitialContent: false`，内容从 Collaboration 扩展同步进 PM，不再用 starter blocks 覆盖。

---

### Q6. `immediatelyRender: false` 是为什么？

**短答：** Next.js 等 SSR/软导航场景下，避免首帧在服务端与客户端不一致导致 **水合后正文空白**。属 Tiptap + App Router 的常见配置。

**源码：** `BlockEditor` 构造函数 `editorProps`。

---

## 5. 面试问答：输入阶段（敲一个字）

### Q7. 在段落里输入一个字母，数据流是什么？

**短答：**

1. 浏览器在 `.ProseMirror` 内产生输入事件。  
2. **EditorView** 根据选区与 schema 生成 **Transaction**（多为段内 text node + mark 变更）。  
3. `dispatch` → 新 **EditorState**。  
4. View **增量更新 DOM**（通常不动 `blockContainer` 外壳）。  
5. Tiptap 触发 `update` → 订阅方可 `pmDocToBlocks` 得到新 `Block[]`。

**易错点：** 日常打字改的是 **blockContent 内的文本**；只有 Enter、删空块、粘贴 MD、Slash 换类型等才改 **块结构**。

---

### Q8. Enter / Backspace 为什么不在默认 Tiptap 段落里处理？

**短答：** 块文档语义由 **`BlockKeymap` + `api/blockManipulation/keymap-handlers`** 实现：Enter 拆块或新建块，Backspace 合并/删空块。`BlockEditor` 的 `handleKeyDown` 对 Backspace 优先走块级逻辑。

**源码：**

- `packages/editor-core/src/core/extensions/block-keymap.ts`  
- `packages/editor-core/src/core/api/blockManipulation/keymap-handlers.ts`

---

### Q9. 粘贴 Markdown 和敲字的终点一样吗？

**短答：** **一样，都是 PM Transaction → View 更新 DOM。** 差异在入口：`handlePaste` → `handleMarkdownPaste` → `markdownToBlocks` → `insertBlocks` / `updateBlock`（`core/api`），不经过 React 重渲染正文。

**源码：** `packages/editor-core/src/core/api/clipboard/fromClipboard/handleMarkdownPaste.ts`

---

## 6. 面试问答：渲染阶段（DOM 长什么样）

### Q10. 一块在 DOM 上典型长什么样？

**短答（示例）：**

```html
<div data-node-type="blockGroup">
  <div data-node-type="blockContainer" data-id="uuid">
    <p>这是一个可编辑的知识文档。</p>
  </div>
  <div data-node-type="blockContainer" data-id="uuid2">
    <h1>标题</h1>
  </div>
</div>
```

**三层对应：**

| 层 | PM 节点 | DOM 特征 |
|----|---------|----------|
| 同级块列表 | `blockGroup` | `data-node-type="blockGroup"` |
| 块壳 + id | `blockContainer` | `data-id` |
| 块类型内容 | paragraph / heading / … | `p` / `h1` / `li` / `table`… |

---

### Q11. 占位符、AI 草稿高亮、评论下划线怎么画上去却不污染文档？

**短答：** **ProseMirror Decoration 插件**（如 `block-placeholder-extension`、AI draft、comment mark）。只改 View 显示层，不把 class 写进协作文档结构；避免 Yjs 里出现纯 UI 状态。

**源码目录：** `packages/editor-core/src/core/extensions/*-extension.ts`

---

### Q12. 图片、画板为什么有时不像普通 `renderHTML`？

**短答：** 使用 **React NodeView**（在 `editor-shadcn` 注入 `imageUploadNode`、`canvasBlockNode`）。PM 文档里仍是块节点，DOM 由 React 组件挂载在 NodeView 槽位。

---

## 7. 面试问答：与协作、保存的关系

### Q13. 本地敲字后，另一台设备怎么看到？

**短答：**

1. PM Transaction → Tiptap **Collaboration** 扩展写入 **Y.XmlFragment**。  
2. Yjs update → WebSocket（Hocuspocus）→ 服务端广播 + 持久化。  
3. 对端合并 CRDT → PM 更新 → 同一套 **EditorView** 重绘。

**注意：** 正文不以 Block[] JSON 入库；Block[] 是按需转换视图。详见 [块模型与编辑器分层面试总结](./块模型与编辑器分层面试总结.md) Q2。

| 层次 | 角色 | 典型 API / 产物 |
|------|------|-----------------|
| **Block[]** | 对外 JSON、MD/AI/测试 | `insertBlocks`、`editor.document`、`markdownToBlocks` |

## 11. 30 秒 / 2 分钟表达模板

### 30 秒

我们对外是 **Block[]**，对内是 **Tiptap + 自定义 blockContainer schema**。用户打字走 ProseMirror Transaction 更新 DOM，不是 React 渲染块数组。`editor.document` 是 `pmDocToBlocks` 的只读视图；协作时 Yjs 才是持久化真相源。

### 2 分钟

挂载时 Provider 创建 `BlockEditor`，组装 extensions，把初始 `Block[]` 经 `blocksToPmDoc` 灌进 PM，再由 `EditorContent` 创建 EditorView。输入时键盘事件变成 transaction：普通字符改 blockContent 里的文本；Enter/Backspace 走块级 keymap。状态更新后 View 增量 patch DOM，外层是 `blockContainer` 的 `data-id`，内层是 `p`、`h1` 等。Tiptap 的 `update` 事件触发后，业务层可以 `pmDocToBlocks` 拿到 `Block[]` 做保存提示或侧栏，但渲染不依赖这份 JSON。协作路径上 Collaboration 扩展把 transaction 同步到 Yjs，与他人设备共享同一 PM 绑定。这样 Block 层服务 API 和 MD/AI，PM 服务编辑体验，Yjs 服务多人与存库。
